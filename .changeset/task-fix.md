'shaft': minor
---

- **`/fix` and `/axonshaft` make changes**: on a pull request, `/fix <what>` and `/axonshaft <prompt>` run the project's Task job, and a bare `/fix` takes the open findings of the last review. With no review yet, or nothing open, a bare `/fix` only replies in one line saying so and ends with a notice. The model edits the head commit's checkout and may run the repo's own install, test, lint, build and format commands. It never gets a GitHub token and can't run `git commit`, `git push`, `gh` or install a package by name. The action then runs the checks again itself, asks the API for a Contents-write token only once they pass, and commits as `axonshaft[bot]` to the pull request's branch through GitHub's API, never forced, revoking the token afterwards. The reply lists the changed files, the commit and each check. If a check fails, nothing is pushed and the reply shows the output.
- **The commands run in a sandbox**: the model's commands and the action's checks run in bubblewrap, with their own PID namespace and `/proc`, no `sudo`, an empty home folder and the checkout as the only folder they can write. Background commands are off, and every sandbox is killed when the session ends, before the change is read. The action installs bubblewrap on an Ubuntu runner when it's missing. Where the sandbox can't start, the task doesn't run and the run reports `sandbox_unavailable`. A task runs only on a GitHub-hosted runner: on a self-hosted one it doesn't run and the run reports `self_hosted_unsupported`.
- **What a commit may hold**: a change under `.github/` (in any case) is refused, and the model can't edit files there. So is a change of more than 200 files, a file over 1 MB or more than 10 MB in all. A change to a `package.json`, a Makefile or a lock file is listed in the reply under "Read before merging". Values of the project's Environment variables are masked in the log and taken out of the reply.
- **Push mode is enforced before the session**: Disabled, a fork's pull request or a branch that is the default branch ends with a reply and a notice saying why, and the run reports `push_failed`. Nothing is ever pushed to the default branch or with `--force`.
- `/fix` and `/axonshaft` on an issue end with a notice.
